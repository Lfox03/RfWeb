# AGENTS.md

RFID attendance system (French UI): npm-workspaces monorepo — TypeScript server (`server/`, Express 5 + better-sqlite3 + node-hid + ws) and React dashboard (`client/`, Vite 8 + React 19 + react-router-dom 7). The legacy JS prototype is deleted; only `rfid/rfidApi.js` + `rfid/rfidWorker.js` remain as the hardware layer, reached exclusively through the `RfidReader` interface (`server/src/rfid/reader.ts`, lazy `require`).

## Commands (always from the repo root)

- `npm run dev` — server (`tsx watch`, `HTTP_PORT`) + Vite 5173. Vite proxies **both** `/api` and `/ws` → `http://127.0.0.1:3000`; the WS hub is mounted at `/ws` on the HTTP port in dev AND prod (the standalone `WS_PORT`/8080 transport is never used by the client). Client code uses **relative URLs only** — never hardcoded localhost.
- `npm run build` — server first (`tsc` → `dist/server/`), then client (`vite` → `client/dist/`). `npm start` = `node dist/server/index.js` (serves `client/dist/` + SPA fallback).
- `npm run typecheck` — **server only**; the client is typechecked by its `tsc` inside `npm run build`.
- `npm run db:migrate` · `db:seed` · `db:verify` (97 checks) · `api:verify` (548 checks).
- No test/lint frameworks: `api:verify` (`server/src/dev/verifyApi.ts`) **is** the test suite — fresh **temp SQLite DB + `RFID_DISABLED` + ephemeral HTTP/WS ports**, ~31 sections covering the whole API, `FakeRfidReader`/`FakeClock`/`setLogSink` injections for hardware/clock/logging tests. **Extend it when adding features.** Neither it nor `db:verify` ever writes `attendance.db` (temp dirs; db:verify also uses a **copy** of the dev DB; handles closed in `finally` for Windows locks).
- `.env` is loaded only from the **repo root** (`config/env.ts` is the source of truth for every env var + default); the DB path `./attendance.db` is **CWD-relative** (override with `DB_PATH`). Node >= 20.12. Native modules (`better-sqlite3`, `node-hid`, esbuild) need install scripts approved if binaries are missing (`npm install-scripts approve better-sqlite3` …).
- Migrations run automatically at every boot. Seed NEVER runs at boot (admin password = `SEED_ADMIN_PASSWORD`, default `admin`; demo cards 9000001/9000002 are skipped if those UIDs are already assigned).

## Architecture

Layers: `api/routers → middleware (auth, validation, error) → services → db/repositories`, and `rfid/reader.ts → scanService → attendanceService → repositories + websocket hub`. Services never touch Express objects; routers never touch SQL or `rfid/`.

- **Boot is idle** (`index.ts`): DB open+migrate → `createApp()` → WS hub → reader monitor → scheduler → wait. **Never starts a session** — the scheduler's boot pass may only materialize future series occurrences as `scheduled` rows. `createApp()` does NOT start the scheduler timer; `api:verify` drives the exported `runSchedulerTick()` directly.
- **DI seams** — one pattern (`setX()` returns a restore fn, active instance resolved per use so hot swaps are honored): **reader** (`getReader()`/`setReader()` in `rfid/reader.ts`; `FakeRfidReader` with `setOnline`/`presentCard`/`pendingReads`), **clock** (`getClock()`/`setClock()` in `core/clock.ts`; `FakeClock.set/advance`), **log sink** (`setLogSink`). Every app timestamp goes through `isoNow()` (`db/types.ts`) → injected clock, including scheduler ticks (`runSchedulerTick(now = getClock().now())`), session stamps, scan/journal times, auth-session expiry, and `POST /sessions` default `scheduledAt`. Deliberate real-time exceptions: `loginRateLimit` (own hook `shiftLoginRateLimitClock`) and logger timestamps. `RFID_DISABLED=1` selects the offline stub (never online, reads never resolve).
- **Session state machine** (`sessionService`): `scheduled→running→completed`; `scheduled|running→cancelled`; anything else 409 `SESSION_INVALID_TRANSITION`. **Mono-lecteur**: at most one `running` (else 409 `SESSION_ANOTHER_RUNNING`). Start works with the reader offline. Start is ONE `db.transaction`: transition + roster snapshot (`sessionRosterRepository.capture` over `resolveExpectedEntries`: inclusion delta wins, exclusion beats group membership, no groups ⇒ nobody expected) + `freezeRoster` stamping `roster_frozen_at` (capture failure rolls back the WHOLE start). Frozen roster ⇒ later group edits never change expected participants.
- **Series recurrence** (`services/seriesService` + pure `services/localTime.ts`, wired to `/api/series` + scheduler generation): `createSeries` validates real-calendar dates **in JS** (SQLite's `date()` normalizes `2026-02-30`→`2026-03-02`, so the CHECKs are NOT the guard), `HH:MM`, IANA tz via `Intl`; weekly ⇒ single `weekday` 0–6 (JS `getDay`, 0=Sunday), daily ⇒ none; `cancelled` is terminal (409 `SERIES_CANCELLED`). `generateOccurrences`/`generateAllActive` materialize `active` series into `app_sessions` over a rolling horizon (`SERIES_HORIZON_WEEKS`, default 12) anchored on the injected clock, "today" in the **series timezone**; idempotency key `(series_id, occurrence_date)` — a date already carrying a row (ANY status) is never touched. Each occurrence stores local `occurrence_date`/`local_time`/`timezone` beside UTC `scheduled_at`, recomputed **per occurrence** so the wall-clock survives DST (nonexistent spring-forward time ⇒ occurrence SKIPPED, never shifted; ambiguous fall-back ⇒ first). Series scope copies into `session_groups`/`session_participants` as `inherited = 1` rows; `editSeriesFrom(id, fromDate, patch)` (ONE transaction): rows before `fromDate` and non-`scheduled` rows survive; matching future `scheduled` rows rewritten IN PLACE (inherited copies resynchronized, `inherited = 0` explicit overrides survive and veto reinsertion); non-matching ones CANCELLED (never deleted); new dates generated. `cancelSeries` non-retroactive. Every series template change (and materializing generation) broadcasts WS `series:changed`.
- **Scheduler** (`schedulerService`, unref'd 10 s tick, started by `index.ts` only): each tick = series generation first (per-series failures isolated), then auto-stop the running session once `now ≥ scheduled_at + duration_minutes` (reason `auto_end`), else start the OLDEST `scheduled` session whose window contains now. A fully **elapsed window never starts** (no catch-up after downtime); early manual starts allowed.
- **Auth** (`authService`, `auth/`): scrypt hashes (`scrypt$N$r$p$saltB64$hashB64`, timing-safe); **persistent server-side sessions** (`auth_sessions`, migration 006) + HTTP-only cookie `sid` (`SESSION_TTL_HOURS` default 12, `Secure` only with `COOKIE_SECURE=1`). No JWT. The opaque 256-bit token travels ONLY in the cookie and is never stored — rows keyed by `token_hash = SHA-256(token)`; logins survive restarts; expired rows rejected + lazily purged. Roles `admin` > `teacher` > `kiosk`; the `kiosk` account is **read-only server-side** (middleware right after `authRequired`: any non-GET/HEAD on `/api` → 403) and satisfies no `requireRole`. Password change destroys that user's OTHER sessions (acting one survives); own-role change → 409 `SELF_ROLE_CHANGE`; `password_hash` never returned. **Local console exception**: a request with NO `sid` cookie at all from the loopback address (`core/loopback.ts` — strictly `127.0.0.1`/`::1`, never the rest of 127/8; `X-Forwarded-For` honored only under `TRUST_PROXY=1`) is attached `LOCAL_KIOSK_USER` (id 0, role kiosk) **GET/HEAD only** (`attachLocalKiosk`, mounted before `/auth` so tokenless `GET /api/auth/me` bootstraps `/kiosk` without login on the server screen). Writes stay 401; a present-but-invalid cookie is NEVER demoted (stays 401; a `sid=` left by logout counts as present); admin-only routes stay 403. Same exception on the WS handshake (registered in the hub with a `null` token, which `closeClientsFor` and TTL sweeps skip).
- **Login rate limiting** (`api/middleware/loginRateLimit.ts` on `POST /auth/login`): in-memory, two fixed-window counters (client IP + normalized username); ANY non-2xx login response counts as a failure; progressive backoff, capped; locked out → 429 `RATE_LIMITED` + `Retry-After`, identical message whatever dimension tripped or whether the account exists. `req.ip` trusts `X-Forwarded-For` only under `TRUST_PROXY=1`. Test hooks `resetLoginRateLimits()` / `shiftLoginRateLimitClock(ms)`.
- **Scan pipeline** (`attendanceService.handleScan(uid)`): EVERY scan journaled in `card_scans` (`accepted|duplicate|unknown|expired|out_of_group|manual`); `app_attendances` written only on the first ACCEPTED scan per (session, student). Expected scope = `sessionRepository.isExpectedParticipant` (no-group sessions accept everyone — legacy). Unexpected student → `out_of_group` (journaled, never counted). Broadcasts `attendance:scanned` — WS payloads **camelCase**, DB rows snake_case. Manual correction: `POST /api/sessions/:id/attendance/manual` `{studentId}` (running only, 409 `ALREADY_PRESENT`, group scope deliberately not enforced, journals `manual`, broadcasts with `uid:""`). `POST /api/reader/next-card` one-shot read: 409 `READER_BUSY` while a session loop holds the reader, 503 `READER_OFFLINE`, 504 `READER_TIMEOUT` (45 s); `POST /reader/beep`.
- **WebSocket** (`websocket/hub.ts` = protocol + module-singleton `broadcastEvent`; `websocket/server.ts` = transport): two transports share one hub (standalone `WS_PORT`, and the `/ws` upgrade on the HTTP server — what the client uses). Events: `status` snapshot on connect (`{"cmd":"get_status"}` re-requests), `reader:status`, `session:started|stopped|updated`, `attendance:scanned`, `attendance:reset`, `series:changed`. **WS auth = the same `sid` cookie, resolved at the handshake** (`verifyClient`, both transports): absent/invalid/expired → HTTP 401. A connection whose session is destroyed (logout, password reset) or whose TTL expires is closed with code **1008** (`sessionStore.onSessionDestroyed` notifies with the token hash; `revalidateConnectedClients` 60 s sweep).
- **Structured logging** (`core/logger.ts`): the ONLY runtime log exit — no `console.*` in server code (dev verify/seed CLIs exempt). One JSON line `{ timestamp, level, component, event, ...context }`; English dotted `event` ids (`scan.accepted`, `auth.login_failed`, …), never French prose. `LOG_LEVEL` env. **Redaction at emit**: `password`/`token`/`sid`/`cookie`/`secret`… → `[redacted]`; `uid`/`decid`/`hexid` masked to last 4 digits. Stack traces ONLY for internal 500s (`errorFields(err, { stack: true })`). Every line (post-redaction) also mirrors into a bounded ring buffer (`core/logBuffer.ts`, `LOG_BUFFER_SIZE` default 500) — the admin `GET /api/logs` tail (second destination beside the sink, so `setLogSink` never starves it; `logBuffer` never imports the logger).

## Database (`server/src/db`)

- SQLite / better-sqlite3, WAL, `foreign_keys=ON`; versioned by `PRAGMA user_version` (**currently 9**) in `db/migrations.ts` (transactional, all-or-nothing).
- Tables: `users`, `groups`, `app_students`, `cards` (uid TEXT UNIQUE **decimal string**; at most one ACTIVE card per student; `revoked_at` NULL = active), `app_sessions` (incl. occurrence columns `series_id` (FK SET NULL) / `occurrence_date` / `local_time` / `timezone` / `roster_frozen_at`; partial UNIQUE index on (series_id, occurrence_date) = generation idempotency key), `session_groups` + `session_participants` (both with `inherited` flag, migration 009), `app_attendances` (UNIQUE(session_id, student_id)), `card_scans` (audit journal, duplicates included), `auth_sessions`, `session_series` + `session_series_groups` + `session_series_participants`, `session_roster` (denormalized snapshot frozen at start, **immutable** via BEFORE UPDATE/DELETE RAISE(ABORT) triggers whose WHEN clauses exempt only the FK SET-NULL/CASCADE shapes).
- UIDs are decimal **strings** end-to-end: `WHERE uid = 1234` (number) never matches — bind strings / `normalizeUid()`. Timestamps: TEXT ISO-8601 **UTC** ms + `Z` (`isoNow()` follows the injected clock); schema `strftime` DEFAULTs truncate to seconds — tolerate ±1 s drift.
- `students` / `sessions` / `attendances` are **compatibility VIEWS** (INSTEAD OF triggers over `app_*`) + `legacy_*` archive tables. The server reads/writes `app_*` only; never `CREATE INDEX` / `CREATE TABLE IF NOT EXISTS` / `RETURNING` against the views (use `lastInsertRowid`).
- Repositories are factories; singletons exported by `db/index.ts` (importing also migrates) as **mutable `let`** rebound by `reopenDatabase()` — the restore feature swaps the DB file at runtime and every service resolves references at call time. Only `services/` and the seed/verify CLIs may use repositories.

## API conventions (`server/src/api`)

- Envelopes via `api/http.ts`: `{data}` | `{data, meta:{total}}` | `{error:{code,message}}`; `asyncHandler` replaces try/catch; SQL details never leak. Hand-rolled validators `api/validate.ts` + `rejectUnknownFields` (unknown body field → 400) + query helpers `qInt/qDate/qEnum` (empty query value = absent).
- Error codes: 401 `NOT_AUTHENTICATED`/`INVALID_CREDENTIALS`, 403 `FORBIDDEN`, 400 `VALIDATION_ERROR`/`INVALID_JSON`/`INVALID_REFERENCE`, 404 `NOT_FOUND`, 409 `GROUP_NAME_TAKEN`/`USERNAME_TAKEN`/`UID_ALREADY_REGISTERED`/`STUDENT_NUMBER_TAKEN`/`CARD_ALREADY_ASSIGNED`/`CARD_ALREADY_REVOKED`/`SESSION_NOT_RUNNING`/`SESSION_ALREADY_RUNNING`/`SESSION_ANOTHER_RUNNING`/`SESSION_INVALID_TRANSITION`/`SESSION_OCCURRENCE_MOVE`/`READER_BUSY`/`SELF_ROLE_CHANGE`/`ALREADY_PRESENT`/`RESTORE_SESSION_RUNNING`/`SERIES_CANCELLED`, 413 `PAYLOAD_TOO_LARGE`, 429 `RATE_LIMITED`, 500 `BACKUP_FAILED`, 503 `READER_OFFLINE`, 504 `READER_TIMEOUT`.
- Public: `GET /api/health`, `/api/auth/*`. Everything else behind `authRequired` — except anonymous loopback GET/HEAD (local kiosk, see Auth). `/api/users`, `/api/backups`, `/api/logs` are admin-only (403 even for the kiosk). `GET /api/logs` reads the redacted ring buffer (filters `level`/`limit`/`since`, returns oldest→newest, `meta.capacity`/`buffered`; no write/clear endpoint).
- **Sessions**: `POST /api/sessions` takes `groupIds` (array, **at least one required**) or legacy `groupId`; both → 400 — plus an optional `participants: [{studentId, included}]` (the same individual inclusion/exclusion deltas a series carries, validated by the shared `vParticipants` and persisted explicit `inherited = 0`; NEVER a substitute for the mandatory group). Every session over HTTP/WS carries `group_ids` (sorted); `app_sessions.group_id` is a never-read legacy mirror. `PATCH /api/sessions/:id` edits only `scheduled` rows; a **series occurrence** refuses `scheduledAt` → 409 `SESSION_OCCURRENCE_MOVE` (moves go through `PATCH /series/:id`); `participants` (when present) REPLACES the session's whole explicit delta set, student-checked in the SAME transaction as the schedule edit (an unknown student → 400 with nothing applied). `GET /api/sessions/:id` returns `participants` (the session's own `session_participants` rows — `SessionDetail`) so a client can pre-fill its picker. `GET /api/sessions/calendar?from&to` (both required, inclusive): occurrences keyed on their CALENDAR DAY — series by **local** `occurrence_date`, standalone by UTC day; rows carry series fields + `group_ids` + `participant_count` (frozen count once started, else live expected count).
- **Series** (`/api/series`, any authenticated role; kiosk GET only): `GET /`, `POST /` (201), `GET /:id`, `PATCH /:id` = edit-from (`fromDate` required and must be an existing occurrence date, else 404; `participants:[{studentId,included}]` replaces the whole series delta list), `POST /:id/pause|resume|cancel` (cancel → `{series, cancelled:[ids]}`; double-cancel or resume-after-cancel → 409). **NO DELETE endpoint.**
- **Reporting** (`/api/reports/*`, read-only): `GET /sessions` (filters `from|to|groupId|status`), `GET /sessions/:id` (roster + summary; branches on `roster_frozen_at`: frozen ⇒ immutable snapshot + off-roster manual marks added as present, never-frozen ⇒ legacy live union), `GET /sessions/:id/export` → raw CSV **file response** (not the envelope), UTF-8 **BOM** for Excel. Date filters are **UTC calendar dates** (`substr(scheduled_at,1,10)`).
- **Student CSV import** (`POST /api/students/import`, raw `text/csv`, 2 Mo max → 413): header `prénom, nom, groupe, email, id` (accents/case/BOM/`;` tolerated); only names required; `id` = card UID to assign; unknown groups created; invalid rows skipped and reported `{line,message}`; valid rows in ONE transaction; returns `{imported, skipped, groups_created, errors}`.
- **Backups** (`/api/backups`, admin-only): `POST /api/backups` = consistent snapshot via better-sqlite3 `db.backup()` (never a direct file copy) into `BACKUP_DIR` as `attendance-YYYYMMDD-HHMMSS[-N].db`; list + download by strict-whitelist filename (traversal-proof, anything else 400). **`POST /api/backups/restore`** (raw octet-stream, ≤ `BACKUP_RESTORE_MAX_MB`): stage temp file **next to the live DB** → validate (magic header, `PRAGMA integrity_check`, schema ≤ target version, core tables) → 409 `RESTORE_SESSION_RUNNING` if a session runs → safety backup of current DB → **strictly synchronous swap** (no awaits: close, remove `-wal`/`-shm`, renames, `reopenDatabase()`) with rollback.

## Frontend (`client/`)

Plain hand-rolled CSS in `src/styles.css` (BEM-ish, CSS variables) — no UI library. All user-facing strings French; server comments French, client comments mostly English — follow the file you edit.

- Layering `pages/ → components/ → hooks/ → api/ → types/`: **pages never call `fetch`** — one `api/<resource>.ts` module per resource through `api/client.ts` (envelope unwrap, `credentials:"same-origin"`, `ApiError`, 401 → login, `toUiMessage()` → French errors, `downloadFile()` for exports, `postRaw()` for the CSV import and `.db` restore upload).
- WS: one `LiveSocket` per tab (`websocket/client.ts`, URL from `location`, backoff reconnect). `WsProvider` (`hooks/useWebSocket.tsx`) holds `connection`/`readerOnline`/`activeSession`, a `serverEpoch` counter bumped by `session:*`/`status` (pages reload lists on epoch change) and `subscribe(event, handler)` for `attendance:scanned`. The handshake rides on the login cookie — nothing special to send.
- Routing: `RequireAuth` guards the shell; `RequireAdmin` gates `/users`, `/database`, `/logs`; `RequireNotKiosk` redirects kiosk accounts to `/kiosk` (rendered **outside AppLayout**, own `WsProvider`); `LoginPage.homeFor(role)` sends kiosk to `/kiosk`; `/reports` `<Navigate>`s to `/sessions` (reporting merged there, selected session in `?session=`). Unknown route → `/`.
- **Kiosk is a pure projection of backend state**: never starts/stops sessions from `/kiosk`; exiting the page never stops anything. On the server machine it opens **without logging in** (loopback exception, zero client changes). `hooks/useKioskState.ts` merges WS snapshot + events + HTTP resyncs; scan feedback 4.5 s auto-dismiss, deduped.
- `GET /sessions/:id/attendance` returns ONLY students who scanned — the expected roster is built client-side from `GET /students` filtered by `session.group_ids`.
- **Sessions page = two tabs** on the same route (weekly **Calendrier** default, **Historique et rapports** via `?vue=historique`). `SessionsCalendar.tsx` reloads on `serverEpoch` and on `session:started|stopped|updated` / `series:changed` (debounced) — `attendance:scanned` must NOT reload the grid. Series blocks placed at `occurrence_date` + `local_time` (wall-clock, DST-proof), standalone at `scheduled_at` in browser TZ; overlaps share column width (`lib/calendar.ts#layoutDay`).
- Planning dialogs (`components/sessions/`): `CreateSessionDialog` (Ponctuelle → `POST /sessions`, Récurrente → `POST /series` — both expose the reusable `StudentPicker` individual-delta editor, empty selection sent as `undefined`); `SessionEditDialog` scope choice: « Uniquement cette occurrence » (`PATCH /sessions/:id` — label/durée, datetime for standalone only; PLUS an individual-participants editor on a STANDALONE one-off, pre-filled from `GET /sessions/:id` and sent as a full replace — occurrences hide it, their selection is managed through the series scope) vs « Cette occurrence et les suivantes » (`PATCH /series/:id`, `fromDate = occurrence_date`). Weekly series = a SINGLE weekday, never a day list. Every 409 toasts the French server message AND triggers a calendar resync.
- Table sorting: `lib/sort.ts` (`sortRows`, French collation, nulls last) + `hooks/useSort.ts` + `components/common/SortHeader.tsx`. Toasts via `hooks/useToast.tsx`.

## Gotchas

- `attendance.db` (+`-wal`/`-shm`) is **live state — never delete or reset it**. A `scheduled` session left in the DB **WILL auto-start itself** on a running server once its window contains now — cancel it to keep the server idle. A `running` session at boot blocks other starts (409) until auto-stopped or `POST /api/sessions/:id/stop`.
- **Port 8080 conflict**: the standalone WS transport may clash with local tooling (e.g. llama.cpp). A failed standalone bind is a non-fatal boot error; the client and dev proxy never use it.
- tsconfig `rootDir: server/src` ↔ `outDir: dist/server` are at **equal depth** so the adapter's `require("../../../rfid/rfidApi.js")` resolves identically under `tsx` and in `dist/` — don't change one without the other.
- Never hardcode mutable dev-DB values (group names…) in `db:verify` assertions — compare against current physical tables.
- Without the USB reader the server just logs `scan.reader_offline` (warn) once per scan-loop start; sessions still start/stop. `RFID_DISABLED=1` silences USB entirely.

## Verify with

`npm run typecheck` · `npm run db:verify` · `npm run api:verify` · `npm run build` · `npm start` — boot must print ONLY the structured JSON lines `db.schema_up_to_date` (version 9), `http.listening`, `ws.listening`, `scheduler.started` (+ `rfid.*`, + `series.occurrences_generated` when active series materialize rows) — **no session is ever started at boot**. Then `GET /api/health` → `{"status":"ok"}` and `POST /api/auth/login` (admin after `npm run db:seed`) → 200 + `sid` cookie. Manual reporting/import/restore testing: throwaway `DB_PATH` + seed, never `attendance.db`.

## Deferred (do not assume they exist)

No global rate limiting (only `POST /api/auth/login`), no HTTPS (`COOKIE_SECURE` only behind TLS), no test/lint frameworks beyond the verify CLIs, no Fastify. No user deletion/deactivation (remove access = password reset or role change). No report pagination/PDF/filtered-range export (per-session export only). No series DELETE endpoint. No dedicated per-occurrence membership-override UI: `PATCH /sessions/:id` DOES write explicit `inherited = 0` rows (a per-occurrence override surviving later series edits), but the planner only exposes that editor on one-off standalone sessions — an occurrence's individual selection is edited through the series scope. No session-group edits after creation (`groupIds` fixed at creation; `PATCH /sessions/:id` = label/duration [+ scheduledAt on standalone] + individual `participants`, never the group set). Compat views + `legacy_*` drop deferred.
